02 · Scans

Names first, then everything else.

Deleting a file mostly just marks its space as free. Lifeline reads back what the file system forgot, and when that's gone too, it finds files by what's inside them.

Quick scan · names, folders, dates

Lifeline reads the records that NTFS, FAT and exFAT leave behind. It rebuilds the folder tree, including folders that were deleted too, and checks every file against the allocation map so you know whether its space has been reused. On NTFS the records are parsed on every CPU core.

  • 3file systems: NTFS, FAT12/16/32, exFAT
  • allCPU cores parse the NTFS MFT
  • 0bytes written to the drive you scan

MFT · $Bitmap · LFN · exFAT entry sets · backup boot sector

Deep scan · by content

After formatting, or on a file system Lifeline can't read, it searches every block for the start of a known file. It then follows that format's own structure (JPEG segments, ZIP directories, MP4 boxes, RAR blocks, Ogg pages) to where the file really ends, and throws away random matches. The work is split across worker processes, each with its own read handle.

  • 20format families, photos to databases
  • ~1 GB/ssearched per worker process
  • 1×each file listed once, even if both scans find it

Lost partitions

Lifeline reads MBR (with logical partitions) and GPT tables, then searches the disk for boot sectors that are no longer listed. It even finds an NTFS volume whose first sector was wiped, using its backup copy. Every candidate is opened read-only before you see it.

MBR · EBR · GPT · 1 MiB + 63-sector alignment

Smart scan

Most people want this one: a quick scan for names and folders, then a deep scan of free space for anything older. A file found by both is listed once, under its real name, so the live count matches what you'll see.

quick → deep · free space only · deduplicated

Thousands of results are only useful if you can find yours. Browse by type or folder, flip to a photo gallery, preview anything, and search like you think.

Search that speaks plainly · and powerfully

Type words, wildcards or filters, and combine them freely. If you mistype a filter, the search just matches less; it never errors. The same language works on the command line.

  • *.docxwildcards on the name
  • type:photos size:>5mbkinds and sizes
  • modified:2024-01..2024-06date ranges
  • in:Documents -backupinside a folder, leaving some out
  • "final draft" re:^IMG_\d+phrases and regex

Recovery chance, in words

Every file is Excellent, Good, Poor or Unlikely, with a sentence that says why. Overwritten files stay hidden unless you ask for them.

Check before you recover

Lifeline reads the files and tests their structure: ZIP and PNG CRCs, JPEG scan data, PDF cross-references, SQLite integrity, RAR/7z/Ogg checksums. Nothing is written.

Save the scan

Keep the results in a .lifeline file and come back tomorrow without scanning a 2 TB drive again.

04 · Safety

First, do no harm.

A recovery tool that writes to the drive it's recovering from can destroy the very files you want. So Lifeline only ever reads, and it won't let you save onto the source drive, even by accident.

It's also honest with you. When an SSD has already erased a file's blocks (TRIM), the preview says so instead of handing you a file full of zeros.

  • ReadsRead-only access to the drive it scans, always
  • GuardsRefuses to recover onto the same drive: drive letters and physical disks, Linux partitions and device-mapper, macOS APFS stores
  • ImagesCopies a failing drive to a file first, skips bad areas then retries them, and resumes if interrupted
  • SectorsA bad sector costs 4 KB, not the whole scan
  • ReportA CSV of every recovered file and its condition

05 · Get it

Runs where you are.

Download one file and run it: no installer, no Python needed. Keep it on a different drive from the one you lost files on, ideally a USB stick.

Go to downloads pip install lifeline-recovery

Windows

Double-click run.bat; it asks for administrator rights, which Windows needs for direct drive access. Or build one portable Lifeline.exe with build_exe.bat.

python -m lifeline

macOS

Run ./run.sh. Lifeline asks for your password to read drives; allow it Full Disk Access too. ./build.sh makes Lifeline.app.

./run.sh

Linux

Run ./run.sh. Lifeline offers to restart itself with admin rights through pkexec, or you can start it with sudo.

sudo -E python3 -m lifeline
terminal
# get it
$ git clone https://github.com/Ojas1024/LifeLine.git && cd LifeLine
$ pip install -r requirements.txt
$ python -m lifeline                 # the app

# or straight from the terminal
$ lifeline scan D: --out E:\Recovered
$ lifeline scan /dev/sdb1 --query "*.docx modified:2024" --out ~/Recovered
$ lifeline partitions /dev/sdb --search
$ lifeline image /dev/sdb /mnt/usb/sdb.img   # resumable
